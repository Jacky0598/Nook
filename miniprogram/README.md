# 校园帮 · 微信小程序原型

对应 `PRD-马来西亚校园服务平台-v1.md` 里的 **P0 MVP 范围**：只做 A 组学业线（课程辅导 + 选课咨询），加上双向发布、搜索比价、订单与评价的骨架。

---

## 一、5 分钟跑起来

1. 下载 **微信开发者工具**（稳定版）：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 打开工具 → 用微信扫码登录 → 左侧选「小程序」→ 点 **+ 导入项目**
3. 目录选到本文件夹 `miniprogram/`
4. AppID 选 **「测试号」**（右下角有个链接，不用注册也能跑）
5. 点「确定」，模拟器里就能看到了

> 不想装工具就先看效果？打开上一级目录的 `预览-小程序原型.html`，浏览器直接看。

## 二、目录结构

```
miniprogram/
├── app.js               全局状态（当前用户、当前学校）
├── app.json             页面注册 + tabBar 配置
├── app.wxss             全局设计变量（颜色、按钮、徽章）
├── project.config.json  开发者工具项目配置
├── utils/
│   └── mock.js          全部假数据 —— 接后端时只改这一个文件
└── pages/
    ├── index/           首页信息流（热门服务 + 求助中）
    ├── explore/         找服务（分类 / 搜索 / 排序 / 并排比价）
    ├── post/            发布入口（双向发布选择）
    ├── publish/         发布表单（含违禁词拦截）
    ├── detail/          服务详情（资质 / 服务边界 / 评价）
    ├── message/         会话列表
    └── me/              个人中心（买家 / 卖家双身份切换）
```

## 三、这版重点演示的三件事

**1. 并排比价（`explore` 页 →「⚖️ 比价」）**
选最多 3 个服务，价格、评分、接单量、资质并排显示在一屏里。
这是整个产品相对小红书和微信群最核心、也几乎是唯一的结构性优势 —— 演示给任何人看，都从这里开始。

**2. 双向发布（`post` 页）**
「我能提供服务」和「我需要帮助」是平级的两个入口，不是招聘网站那种甲方发布、乙方投递的单向结构。
同一个账号在 `me` 页可以一键切买家 / 卖家视角。

**3. 合规拦截（`publish` 页）**
标题或详情里写「代写」「代考」「代刷」「答案」等词会被直接拦下。
详情页有明确的「服务边界」区块，写清楚讲什么、不碰什么。

> ⚠️ 前端违禁词只是提前拦截、降低误发。**这套规则必须同时实现在后端**，否则绕过前端直接调接口就能发出去。

## 四、接后端要改什么

现在所有数据都在 `utils/mock.js`，页面只调用它导出的几个函数。接后端时：

```js
// 改前
getHotListings() { return LISTINGS.filter(l => l.hot); }

// 改后
getHotListings() {
  return new Promise((resolve, reject) => {
    wx.request({
      url: 'https://api.你的域名.com/listings/hot',
      success: res => resolve(res.data),
      fail: reject
    });
  });
}
```

页面里对应改成 `.then()` 或 `async/await`。**页面结构和样式不用动。**

需要的接口大致这些：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/auth/login` | POST | 收 `wx.login` 的 code，换 openid + 会话 |
| `/verify/email` | POST | 发校园邮箱验证码 |
| `/verify/email/confirm` | POST | 校验验证码，升到 L1 |
| `/verify/transcript` | POST | 上传成绩单，进人工审核队列 |
| `/listings` | GET | 列表，带 `category` `keyword` `sort` `school` 参数 |
| `/listings/:id` | GET | 详情 |
| `/listings` | POST | 发布服务（**后端必须再跑一遍违禁词**） |
| `/requests` | GET / POST | 需求列表与发布 |
| `/quotes` | POST | 对需求报价 |
| `/orders` | POST / PATCH | 创建、确认、完成订单 |
| `/reviews` | POST | 提交评价 |
| `/reports` | POST | 举报 |

## 五、上线前必须处理的事

- [ ] **注册小程序主体** —— 马来西亚 Sdn Bhd 走境外主体（免 ICP 备案、免年审），公司名须与 SSM 注册证书完全一致；注册后 **45 天内**必须完成微信认证，否则作废
- [ ] **服务器域名白名单** —— 小程序只能请求在管理后台配置过的 HTTPS 域名，且需要有效证书。建议服务器放新加坡节点
- [ ] **后端违禁词校验** —— 前端那套只是体验层
- [ ] **校园邮箱白名单** —— 各校邮箱后缀要逐个确认后加入，别写死一个
- [ ] **人工审核后台** —— 成绩单认证、举报处理、违规下架都需要人工，这个后台和小程序同样重要
- [ ] **用户协议与隐私政策** —— 小程序审核必需，且要说明成绩单截图这类敏感信息如何存储和销毁
- [ ] **房产 / 留学板块暂不开放** —— 见 PRD 第 6 节，需先完成合规确认

## 六、已知的原型简化

以下都是**故意没做**的，不是 bug：

- 无真实登录，用户写死在 `app.js`
- 无真实网络请求，全部本地假数据
- 会话列表点开是弹窗提示，不是真的 IM
- 发布表单不落库
- tabBar 用文字 + emoji，没做图标切图
- 无分包，无骨架屏，无错误边界

## 七、下一步建议

按优先级：

1. **先拿这个原型去问 20 个真实学生** —— 别急着写后端。重点问两件事：会不会在这里挂牌接单，以及愿意为选课咨询付多少钱
2. **确定公司主体**，启动小程序注册（45 天认证时限从注册那天开始跑，别拖）
3. **搭后端 + 人工审核后台**
4. **手动招募 50 位种子服务者**，创始人亲手帮他们填资料 —— 这一步比写代码重要得多

冷启动策略详见 PRD 第 11 节。
